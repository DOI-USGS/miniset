Miniset WASM + proj4js Browser Example

This example demonstrates the recommended workflow for spatial reference extraction in the browser.

Workflow:

  1. Load DEM file (user upload or fetch from server)
  2. Extract WKT string from file metadata (server-side or pre-extracted)
  3. Parse WKT with proj4js (pure JavaScript, runs in browser)
  4. Create DEM with explicit ellipsoid parameters
  5. Query elevations with correct planetary ellipsoid

Alternative: Using setEllipsoid()


// Create DEM with default ellipsoid
const dem = new Module.GdalDEM('/tmp/dem.tif', Module.DEMType.HEIGHT);

// Later, set the correct ellipsoid
dem.setEllipsoid(semiMajor, semiMinor);

Server-side WKT Extraction (Node.js)


// Extract WKT using native GDAL (runs on server)
import { execSync } from 'child_process';

function extractWKT(demPath) {
    const output = execSync(`gdalsrsinfo -o wkt1 "${demPath}"`, { encoding: 'utf8' });
    const wktMatch = output.match(/(PROJCS|GEOGCS)\[[\s\S]*\]/);
    return wktMatch ? wktMatch[0] : null;
}

// Send WKT to browser along with DEM file
const wkt = extractWKT('mars_dem.tif');

Why This Approach?

  • Browser Compatible: proj4js is pure JavaScript, no C++ exceptions
  • Planetary Support: Works with Mars, Moon, and other planetary bodies
  • Clean Separation: Spatial reference parsing in JavaScript, raster operations in WASM
  • No Database: Avoids PROJ database access that causes C++ exceptions in WASM
